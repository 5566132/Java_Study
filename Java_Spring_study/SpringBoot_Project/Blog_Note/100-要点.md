## 分页
自己手动分页可以让前端在请求参数传递page 和 size两个变量
封装一个PageRequest\<T>作为分页的返回结果传递给前端
```
//创建一个分页类, 返回需要分页的数据  
//也就是需要分页返回的数据都用这个类包装返回  
@Data  
public class PageRequest<T> {  
    private int page;  
    private int size;  
    private boolean hasMore;  
    private T data;  
}
```
数据作用分别是记录当前页和每页的大小, 记录是否还有下一页, data记录返回的所有数据
用page和size在service层算出偏移量offset然后传递到mapper层
在mapper层用 limit 偏移量, 每页大小 去做到分页请求部分变量



## 获取数据最好排序
也就是在select语句用个order by id之类的排好序再使用分页, 因为他说有的情况搜索优化啥的可能不会按照id的顺序了, 

## 大重点
这个分页伟大的程序员想出了一种完全不同的分页方式
首先, 我们知道要用order by让数据有序
然后既然已经有序了, 我们是不是可以使用 where id > 20去高速获取21条开始的数据
这个时候我们传递的自定义类PageRequest\<T>就有大作用了, 其实主要是page和size发挥作用
根据这个我们可以计算出偏移量(等等 , 用limit的时候也需要呀)
然后直接where id > offset高速计算出要从哪里开始获取数据
然后 where id > offset limit size 就能快速获取
**但是, 这个思路是错的, 这个Page和size的写法只适合limit分页**
**因为, 数据可能是不连续的, 你无法根据page和size知道该轮到哪个id了, 可以理解吗, 用id > offset这个方法要保证前面正好有page`*`size个数据, 但是你为无法保证这些数据是从1开始连续的***
==🔴**所以, 要记录一个游标cursor也就是上一次到哪个号码了, 这样id > cursor就完美适配了**==
