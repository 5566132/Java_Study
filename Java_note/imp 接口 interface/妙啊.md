接口也可以直接创建对象, 但是一般应该是不会这么做的,但是我现在知道一个特例
这个跟内部类有关系

一般私有内部类都是没法访问的
Outer.Inter1 t1 = new Inter1();
Outer.Inter1 t1 = o1.createInter1();
这类写法都会报错

所以一般不会去接收内部类, 一般都是我先用内部类去实现接口, 然后再内部类里面重写这个接口, 接着再在外部类的里面写个new这个内部类的方法, 最后**可以在测试类里面用接口接收这个new**, 也就是接收内部类里面重写的接口里面有的方法, 
比如一个Interface1 类型的接口里面有个show()方法
直接看代码解释
public class Outer {  
    private int age;  
    Outer(){  
        age = 0;  
    }  
    Outer(int age) {  
        this.age = age;  
    }  
    //私有的内部类  
    private class Inter2 implements Interface_show{  
        public String name;  
        Inter2(){  
            name = "";  
        }  
        Inter2(String name){  
            this.name = name;  
        }  
        //重写接口的抽象方法
        @Override  
        public void show(){  
            System.out.println(name);  
        }  
    }  
    //无参创建私有内部类  
    public Inter2 createInter2(){  
        return new Inter2();  
    }  
    public Inter2 createInter2(String name){  
        return new Inter2(name);  
    }  
}
接口里面只有一个show()方法需要重写
public interface Interface_show {  
    public void show();  
}

public class Test1 {  
    public static void main(String`[]` args){  
        Outer o = new Outer();
        Interface_show obj = o.createInter2("private内部类的姓名展示");
        obj.show();
    }  
}
我觉得这里非常巧妙, 一个子类实现接口其实就真的可以理解成这个子类继承了这个接口, 也就是接口是子类的父类, 所以, 完全可以用 父类的左值 去接收 子类的右值, 这就是多态, 理所当然可以调用show()方法
