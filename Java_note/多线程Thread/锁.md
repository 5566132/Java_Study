有两种方式可以发挥锁的作用
synchronized关键字
synchronized这个关键字用于给指定的代码块上锁, 如果作为方法的关键字就相当于给方法上锁
synchronized void run(){}; -> 给方法上锁
void run(){
	synchronized(引用类型数据){
		代码
	}
}
这个括号里面传递的可以是任何引用数据类型, 比如Object的对象, Thread.class(Thread这个类的class对象)
也就是说, 这个传递过去的东西就类似一个标识, 虽然本身不是锁, 但是起到和锁一样的效果, 如果对于不同线程传递的这个对象是同一个那就能起到互斥锁的作用了

Lock接口
目前知道其下的ReentrantLock类即可
Lock l = new ReentrantLock();
这就创建了一个锁
l.lock(); -> 尝试获得锁, 未获得就直接阻塞, 也就是不会产生自旋效果
l.unlock(); ->释放锁

public class myThread extends Thread{
	static Lock l = new ReentrantLcok();
	static int num = 0;
	@Override
	public void run(){
		while(true){
			l.lock();
			try{
				if(num < 100){
					num++;
				}else{
					break;
				}
			}finally{
				l.unlock();
			}
		}
	}
}
这就是一个正常的写法(一般业务都是这么写, 要不就用synchronized), 循环先尝试拿到锁, 
这个try一部分原因是为了让释放锁的部分写的更方便, 
拿到锁之后就先执行try内部的代码, 无论如何执行完都会执行finally, 也就是会释放锁
