MVCC这个规则都是一样的, rr和rc有区别的原因是因为这个的使用时机不同, 一会儿再说, 先说机制

首先要知道 InnoDB引擎所在没手动开启事务的时候所有语句都是一个独立的事务
首先要知道事务有两种手动开启方式
start transaction
这方式在执行的瞬间就会为本事务创建一个Read View
begin
这个方式在执行第一个sql语句才会创建Read View
这个创建时机有差别, 但是不影响MVCC的机制

## MVCC规则, 也就是快照读看到哪个版本数据的规则
首先根据Read View 给事务划分
![[Pasted image 20260921005219.png]]
**可不可见指的是行数据对于本事务是否是可见的**
对于本事务可见:
如果某行的trx_id显示的事务id大于 max_trx_id 那么这个版本的数据对于本事务就是不可见的
如果trx_id 在min_trx_id 和 max_trx_id之间, 那就要去查m_ids这个列表, 如果这个trx_id在这个列表, 那就不可见, 反之可见

对于本事务不可见:
trx_id是本事务的都可见
如果某行的trx_id显示的事务id小于min_trx_id 那么就可见

理解:
这其实就是保证了所有在本事务开启前做出的修改都对本事务可见, 在本事务之后做出的修改则都不可见, 在本事务开启时没关闭的事务的任何修改版本都不可见

现在知道了, 行数据的可见标准, 所以就要利用undo log记录的版本链去回退版本找到可用版本, 这里的规则是找到第一个可用版本就作为快照读的依据, 也就是沿着
undo log版本链回退碰到第一个可用版本就直接沿用为快照
