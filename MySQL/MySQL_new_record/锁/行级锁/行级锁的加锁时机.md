上锁规则相较于不同索引会有些差异
但是有一个要知道的前提是 **锁是锁在索引上的**
先说单列索引
## 单列索引上锁规则
**主键索引**(聚簇索引), **二级唯一索引**( 二级索引就是对非主键字段创建的单列索引, 唯一索引就是针对unique字段创建的unique修饰的索引 )
对于 where 等值查询, 如果存在这个值, 那就只对这个字段加上record lock如果不存在就这个索引所在的区间加上间隙锁
对于 where 范围查询, 直接举例吧 存在 1 4 10 20 索引, 范围查询6 15就会上间隙锁(4, 20)同时把内部的10上record lock

**二级非唯一索引**, 有一个不同点是等值查询命中会找一个最近的左区间去上一个临键锁
比如 命中10 , 然后10的左边最近的索引是4 就上一个 ( 4, 10 ] 的临键锁
当然, 这个索引都是非唯一的了, 那肯定要把所有的这个等值索引都加上record lock
细说一下 非唯一索引等值查询, 假设有非唯一索引age这个字段, 和主键id  ( id , age )
存在 ( 3, 10 ) ( 5, 20 ) (10, 20) ( 15, 20 ) ( 30, 39 );
**那我对age = 20 进行等值查询, 就会产生临键锁 age ( 10 , 20 ] 和 ( 20 , 39 )首先要明确这个临键锁是针对age索引, 然后会返回主键索引去在 id = 5 10 15的行创建 record lock** 
所以, ( id = 7 , age = 20 )这类数据不可以插入理论上是因为这个数据在age索引的位置是在  ( 5, 20 ) (10, 20) 这两个之间的, 然后由于 后者被记录为间隙锁, 所以不可以插入
那( id = 7 , age = 10 )则是一样的原因 , 这个行插入age索引, 在( 3, 10 ) ( 5, 20 )之间, 在间隙锁范围内,所以没法插入

## 间隙锁上锁逻辑总结
在我看来, 你只需要搞清楚 间隙锁是为了解决幻读问题, 就能完全推出对于不同类型的索引会在什么范围上锁
比如在 唯一索引( 主键索引 和 二级唯一索引 ) 每个键都只有一个, 等值查询甚至不需要间隙锁, 所以只会给这个行加入 record lock 但是没命中值, 或者范围查就需要用间隙锁锁上相邻区间
在 非唯一索引, 等值查命中就必须保证这个值的每次查询都不能新增行, 所以会给一个范围挂上间隙锁去保证这个值不会新增行, 那只能用这个值对应的索引的左侧和右侧最近索引作为区间范围了
