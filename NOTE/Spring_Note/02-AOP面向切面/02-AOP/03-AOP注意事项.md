首先AOP是一种面向切面编程的思想, 目的是在保留源代码功能的同时添加我希望的功能
事务也是依靠AOP思想实现的, 代理就是AOP思想的具体实现方式
其实没必要把这个东西想得很高端, 就是为对象创建了一个子类(也可以是实现了同一个接口的类), 用新增功能包裹原对象调用方法 -> 这也就是代理的作用

所以要注意代理类和原类的关系要不就是二者实现了同一个接口, 要不就是代理类继承了原类, 所以, 根据接口或者继承的规则你可以自己去推理哪些方法可以被代理, 哪些不可以被代理

**AOP思想依靠代理实现, 所以一定要记住代理中方法的执行顺序, 尤其别忘了代理是用周边代码包裹对原方法的调用, 注意是原方法, 不是被spring创建的对象的方法, 所以这个调用应用不到Spring里面的自动配置啥的, 就相当于new了个对象然后调用里面的方法而非利用spring创建了个对象使用**
