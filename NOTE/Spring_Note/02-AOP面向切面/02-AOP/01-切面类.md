一般实现AOP都是创建一个切面类去实现, 

@Aspect
这个注解是通知spring本类是切面类, 主要是要扫描内部的切点注解
@Component
这个也是必备的, 有了这个组件才能将切面类变成bean使用
@Order(x)
调节切面类的优先级关系, 数字越小优先级越高

切面类内部的注解

## @Pointcut切点
就是指定切面类的生效范围, 配置时要注意定位到 类内的方法(也就是必须以方法作为结尾)
@Pointcut( "execution( 权限 返回值 包.类.方法(参数) )" )
除了权限可以省略不写, 其他必须严格配置
返回值可以用 `*` 通配
后面的类, 方法啥的也可以用 `*` 通配
com.atguigu.`*`.`*`(..)
你可以回想一下, 类名本身就是包名加类名的组合, 也就是说 `*`(..)之前的就是一个完整的类名
所以这个格式完全可以看作 类.方法(参数)
然后类又可以分成 包.类
有时候想要表示某个包以及其子包下面的所有类的任意参数的方法
com..`*`.`*`(..)  -> 注意com后面有两个 . . 

只有切点不能让AOP生效, 还要有通知
## 通知
@Before在执行目标方法前执行
@After目标方法后
@AfterReturning正常return之后
@AfterThrowing抛出异常时
@Around环绕通知, 可以实现全过程并且优先级高于前四个, 
只看定义其实After 和 AfterReturinin的执行时机有点难理解
这个时候就出现了Around了
先跳转看一下什么是代理[[02-代理到底是什么]]
知道了代理就可以更好了解**通知**的工作原理

@Around
@JoinPoint(省略)
public void AroundMethod( ProceedingJoinPoint pjp ){
	//接收返回值
	Object obj = null
	try{
		执行原方法前要执行的代码 -> Before
		obj = pjp.proceed(); 执行原方法
		正常取得返回值之后要执行的代码 -> AfterReturning
	}catch( Throwable ta ){
		接收到异常时要执行的代码 -> AfterThrowing
	}finally{
		目标方法全部完毕之后要执行的代码 -> After
	}
}

Around是让我自己手动封装的, 所以我可以决定原方法执行的时机, 这四个时机也就对应了前四个注解的执行位置, 但是这个只是便于你理解前四个注解, 也就是说前四个注解也是相对于原方法按照这个位置放置的, 这五个注解的真实执行顺序如下
有返回值无异常
1. **@Around 环绕通知里 pjp.proceed () 之前的代码**（环绕前置）
2. **@Before 前置通知**
3. 执行目标方法
4. **@AfterReturning 返回通知**
5. **@After 最终通知**
6. **@Around 环绕通知里 pjp.proceed () 之后的代码**（环绕后置）
7. **@Around 的finally里面的代码**

有返回值有异常
1. **@Around 环绕通知里 pjp.proceed () 之前的代码**（环绕前置）
2. **@Before 前置通知**
3. 执行目标方法 -> 异常出在这里
4. ~~**@AfterReturning 返回通知**~~ -> 有异常之后位于发生异常之后的代码都不会执行了, 也就是@AfterReturning 和 @Around中 proceed()之后的代码都不执行了, 转而去执行catch异常的代码
5. @AfterTrowing 接收异常
6. **@After 最终通知**
7. ~~**@Around 环绕通知里 pjp.proceed () 之后的代码**（环绕后置~~）-> 这个不执行了
8. **@Around 里面的接收异常catch的代码**
9. **@Around 的finally里面的代码**

大概就是这么个包裹的结构, around在外层, 剩下四个在内层
