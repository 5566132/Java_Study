## 一、为什么改版（合理性评估）

1. **学习风格验证**：计网/OS 是"思想"、项目是"手艺"——**手艺先行、思想穿插**。
2. **顺序纠正**：不先学老 Spring（XML 版 80% 死知识，SpringBoot 自带 IoC/AOP 概念）；不先学完 Redis（黑马点评就是"项目学 Redis"的课）。
3. **项目不过时**：苍穹外卖是黑马 2023 官方项目，SpringBoot 2.7 + **MyBatis-Plus** + Redis 技术栈 2026 年仍是主流（判断标准看技术栈不看年份）。**但项目本身已烂大街**——定位为练手过渡，要上简历必须二开（[[02-项目规划]] "项目0"）。
4. **三个风险控制**：
   - Redis 不用先系统学完 → 跟黑马点评项目学；
   - 老 Spring 单独课程 → **已学完，不用再补**；
   - 计网设死线 **2027.06 投实习前**系统过一遍（权重 25%，不能无限拖）。

## 七、MySQL 进度备注（2026-09-21 考察结论 · 已达标超前）

**已精熟**（真懂非背）：MVCC 可见性四规则、RR/RC ReadView 时机、快照读 vs 当前读、行锁（Record/Gap/Next-Key、二级索引等值双侧锁）、聚簇/二级/回表/覆盖索引。

**待补**：
- [ ] **ACID** 四性各靠什么：原子性→undo log；一致性→前三者共同；隔离性→锁+MVCC；持久性→redo log
- [ ] **死锁**：四条件（互斥/持有并等待/不可剥夺/循环等待）+ 避免（统一加锁顺序）+ 排查（`show engine innodb status`）
- [ ] **B+树补两点**：叶子有序+双向链表→范围查询；vs 哈希/红黑树对比
- [ ] **联合索引两个细节**：范围右侧失效（`a>10 AND b=1` → b 失效）；`(a,b,c)` 下 `a=1 ORDER BY c` 不走索引→filesort

> MySQL 已远超项目前置要求，阶段 2-3 不需要再分时间给 MySQL；上述待补项用碎片时间 1-2 天补完即可。
