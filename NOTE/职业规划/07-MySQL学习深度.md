## 第 1 档 · 索引（必考，第 1 优先）

**到什么程度**：能把「为什么用 B+ 树」讲到 3 层深度，能徒手画图。

**要学的内容**：

1. **为什么 B+ 树适合索引**（对比哈希 / B树 / 红黑树）
   - 必会：矮胖树 → 磁盘 IO 次数 = 树高；叶子节点有序 + 双向链表 → 范围查询快；非叶子节点只存键 → 单页能存更多键 → 树更矮
   - 加分：聚簇索引叶子存整行、二级索引叶子存主键 → 回表
2. **索引类型**：主键 / 唯一 / 普通 / 联合；覆盖索引（不回表）
3. **索引失效场景**（必背 ≥5 条）：破坏最左前缀、对索引列做函数/运算、隐式类型转换、like 前置通配符、OR 连接非索引列、not in / is not null
4. **为什么建议自增主键**：避免页分裂、叶子有序、非叶子页重排开销
5. **联合索引最左前缀**：能画 `(a,b,c)` 的匹配顺序

**面试常问（用这些题自测深度）**：
- 为什么 MySQL 用 B+ 树，不用 B 树 / 红黑树 / 哈希？
- 联合索引 `(a,b,c)`，`where b=? and a=?` 走不走？`where a>? and b=?` 呢？
- 覆盖索引是什么？为什么能优化查询？
- 为什么推荐自增主键，而不是 UUID？

**过关标准**：
- [ ] 徒手画 B+ 树结构，标出聚簇 / 二级索引叶子分别存什么
- [ ] 背出 ≥5 条索引失效场景，且每条能解释原因

## 第 2 档 · 事务与隔离级别（必考）

**到什么程度**：能背出 4×3 表格，能举幻读实例。

**要学的内容**：
1. ACID 四性**分别靠什么保证**：原子性→undo log；持久性→redo log；隔离性→锁 / MVCC；一致性→前三者共同
2. 四种隔离级别 + 各自防什么：脏读 / 不可重复读 / 幻读
3. 可重复读下如何解决幻读：**快照读靠 MVCC，当前读靠间隙锁**

**面试常问**：
- 可重复读和幻读的区别？（幻读 = 同一查询两次结果行数不同）
- MySQL 默认隔离级别是什么？为什么用可重复读（不是读已提交）？

**过关标准**：
- [ ] 默写表格：隔离级别 | 防脏读 | 防不可重复读 | 防幻读
- [ ] 举一个幻读的具体业务例子

## 第 3 档 · MVCC（拉开差距的核心，必讲透）

**到什么程度**：能不看笔记，完整讲「一条 select 在可重复读下怎么读到快照」。

**要学的内容**：
1. **undo log 版本链**：每个版本带 trx_id（事务 id）和 roll_pointer（指向上个版本）
2. **ReadView 读视图**：四个关键字段 `m_ids / min_trx_id / max_trx_id / creator_trx_id` + 四条可见性判断规则
3. **可重复读 vs 读已提交**：ReadView 生成时机不同
   - 可重复读：**事务内首次 select 生成一次**，之后复用 → 读到一致快照
   - 读已提交：**每次 select 都重新生成** → 读到别人已提交的新数据

**面试常问**：
- MVCC 如何实现可重复读？（README 已列为必背）
- 为什么说 MVCC 是"非阻塞读"？（读写互不阻塞，读不加锁）
- 加分的追问：当前读（for update）怎么走？——回到锁，接第 4 档

**过关标准**：
- [ ] 不看笔记，画出「版本链 + ReadView」并讲清可见性规则
- [ ] 对比 可重复读 / 读已提交 的 ReadView 生成时机差异

## 第 4 档 · 锁（常考）

**到什么程度**：能说出 Next-Key Lock 的锁定范围并举例。

**要学的内容**：
1. 粒度：表锁 / 行锁 / 意向锁（意向锁 = 表锁与行锁的协调信号）
2. 行锁三种类型：
   - **Record Lock**（记录锁）：锁一行
   - **Gap Lock**（间隙锁）：锁区间，防插入 → 防幻读
   - **Next-Key Lock**（临键锁）= 记录锁 + 间隙锁，**InnoDB 默认行锁范围**
3. **死锁**：四个必要条件、如何避免（统一加锁顺序）、MySQL 怎么处理（死锁检测 / 锁等待超时 `innodb_lock_wait_timeout`）

**面试常问**：
- 什么情况行锁会退化为表锁？（索引失效走全表扫描时）
- 间隙锁解决什么问题？什么场景触发？
- 死锁怎么排查？——`show engine innodb status` 看 LOCK WAIT / deadlock

**过关标准**：
- [ ] 能说出 Next-Key Lock 的锁定范围（例：`where id between 5 and 10` 锁哪些区间）
- [ ] 能讲清死锁四个必要条件 + 一个具体排查命令

## 第 5 档 · InnoDB 底层 + 日志 + 主从（必会大部分）

**到什么程度**：能完整讲「一条 update 从发起到落盘」的流程——这是高频大题。

**要学的内容**：

1. **一条 update 的执行流程**（背熟）：
   - 连接 → 解析 → 执行器调存储引擎
   - **Buffer Pool**（内存缓存页）中找数据页，没命中就磁盘读页
   - 修改前写 **undo log**（回滚 + 版本链）
   - 修改后写 **redo log**（WAL 预写日志，崩溃恢复用，**顺序写**）→ 事务提交
   - **binlog**（归档，主从复制用）→ 提交时 redo 两阶段提交（prepare → commit）
   - 内存页脏了，后台**刷盘**（异步）
2. **三种日志对比**（必背）：
   | | redo log | undo log | binlog |
   |---|---|---|---|
   | 层级 | InnoDB 引擎 | InnoDB 引擎 | MySQL Server 层 |
   | 作用 | 崩溃恢复（持久性） | 回滚 + MVCC | 主从复制 / 归档 |
   | 物理/逻辑 | 物理（页变更） | 逻辑 | 逻辑 |
3. **主从复制**：binlog → 从库 relay log → 回放；读写分离；异步 / 半同步（名词了解）
4. **explain 调优**：type（const→eq_ref→ref→range→index→ALL）、key、rows、Extra 里的 `using filesort / using temporary` 是什么

**面试常问**：
- 一条 update 语句的执行过程？（redo/undo/binlog 顺序）—— **高频**
- 为什么需要 redo log，直接改磁盘不行吗？（随机写 vs 顺序写，速度差百倍）
- redo log 为什么是两阶段提交？（保证 redo 和 binlog 一致）

**过关标准**：
- [ ] 完整讲出「update 一条记录」从连接 → 缓存 → 日志 → 落盘，能画图
- [ ] 能说出 redo / undo / binlog 三者职责，并任意两两对比

## 避坑提醒

- ❌ **别去看存储引擎对比之外的东西**（InnoDB / MyISAM 区别要会，但不用研究 Archive 等冷门引擎）
- ❌ **别背"调优参数表"**——面试官要的是原理，不是参数值；参数是 DBA 的事
- ❌ **别跳过 explain**——这是从"会 SQL"到"会 MySQL"的分水岭，面试高频
- ⚠️ **MySQL 定位是"巩固"不是"主攻"**：大二上的主线优先级是 Java 语法 + 计算机网络，MySQL 只要在时间线内过完这 5 档就行，不必反复刷
