## 二、MySQL 面试重点

### 1 · 索引（最高频）
- 🔴 **为什么用 B+ 树**：对比哈希（不能范围查）、B 树（叶子不串链表，范围查慢）、红黑树（太高，IO 多）
  - 答法：矮胖树 → 磁盘 IO 次数 = 树高；叶子有序 + 双向链表 → 范围查询快；非叶只存键 → 单页存更多键 → 树更矮
- 🔴 **聚簇 / 二级索引 + 回表 + 覆盖索引**：聚簇叶子存整行，二级叶子存主键；回表 = 再查一次；覆盖索引 = 不回表
- 🔴 **联合索引最左前缀** + **索引失效 ≥5 条**（每条约 10 秒解释）：破坏最左前缀、函数/运算、隐式类型转换、like 前置通配符、OR 连非索引列、not in/is not null
- 🔴 **为什么推荐自增主键**：避免页分裂、叶子有序

### 2 · 事务与并发
- 🔴 **ACID 各靠什么**：原子性→undo log；持久性→redo log；隔离性→锁/MVCC；一致性→前三者共同
- 🔴 **四隔离级别** + 脏读/不可重复读/幻读 对照表；**MySQL 默认可重复读，为什么**
- 🔴 **MVCC 实现可重复读**：undo 版本链 + ReadView 四规则；快照读 vs 当前读（当前读靠间隙锁防幻读）
- 🔴 **锁**：Record / Gap / Next-Key Lock；**行锁退化表锁**（索引失效走全表）；死锁四条件 + 排查命令 `show engine innodb status`

### 3 · 日志与性能
- 🔴 **一条 update 全流程**（必背大题）：连接 → Buffer Pool 找页 → 写 undo → 写 redo（两阶段提交 prepare→commit）→ binlog → 异步刷盘
- 🔴 **redo / undo / binlog 对比**：引擎层 vs 引擎层 vs Server 层；崩溃恢复 vs 回滚+MVCC vs 主从复制
- 🟡 **explain 调优**：type（const→eq_ref→ref→range→index→ALL）、rows、Extra（using filesort / using temporary 是警告）

### 🟡 加分
- 分库分表时机一句话、XA/TCC/Seata 名词、主从复制 binlog→relay log

## 三、Redis 面试重点

### 🔴 必会
1. **为什么快**：内存 + 单线程（无锁竞争）+ IO 多路复用（epoll，联动 [[10-操作系统面试重点]]）
2. **缓存三大问题**（背熟解决方案）：
   - 穿透：查不存在的数据 → 布隆过滤器 / 缓存空值
   - 击穿：热点 key 过期瞬间 → 互斥锁 / 逻辑过期
   - 雪崩：大量 key 同时过期 → 过期时间错开 / 多级缓存
3. **分布式锁**：setnx + 过期时间 + 可重入（Redisson 看门狗续期）；*"和数据库乐观锁怎么配合"*（秒杀联动 [[02-项目规划]]）
4. **持久化 RDB vs AOF**：快照 vs 追加日志；各自优缺点、怎么选（允许丢数据用 RDB，要稳用 AOF）

### 🟡 加分
- **缓存一致性**：Cache Aside / 延迟双删 / 为什么先删缓存后更库有问题
- **过期策略**（惰性 + 定期）、**淘汰策略**（8 种，LRU/LFU）
- **底层数据结构**：SDS/跳表/压缩列表/整数集合；*"zset 为什么用跳表不用红黑树"*（实现简单 + 范围查找方便）
- 集群名词：主从/哨兵/Cluster（了解级）
