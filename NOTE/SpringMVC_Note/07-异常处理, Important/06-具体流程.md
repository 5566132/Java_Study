你记得吧, 全局异常处理类, 这个类就是用来处理从Controller层抛出的异常的( 可以回忆一下, 异常不处理就会向上抛出, 所以Dao等层级的异常都会被Controller层接收到, 然后从Controller层抛出的异常就会来到全局异常处理类找到对应得到异常处理方法 )
所以要写个全局异常处理类去处理从Controller层中抛出的异常, 而Controller只需要把异常都抛出就行了 , 处理代码写在异常处理类中

但是, 大部分异常我应该都是不关心他是什么类型的, 我只需要知道出了异常, 然后知道是在哪个地方出的( 也就是知道这个异常的响应体状态码 ), 然后在前端给用户做出相应的提示就足够了
所以, 我直接就规定, 业务中的所有异常都被划分到RuntimeException这个异常(具体为什么选择这个可以再问问ai 我就不细说了, 因为我没了解), 但是光划分范围还不够, 因为你希望的场景是 , 全局异常处理类接收到这个异常, 然后这个异常内部有code, msg等信息, 这样你才能封装成响应体传递给前端, 
所以要创建一个异常类( BizException )去继承RuntimeException这样这个类对象就能作为异常被异常处理类接收, 同时传递异常的状态信息了

但是这里又出现了一个老生常谈的问题, 异常的种类过多, 我不能每次传递某种异常的时候, 也就是new BizException 的时候都把具体的 code msg 传递给这个异常类, 而是用某个东西去代表我要传递的信息, 每次传递都是传递这个东西, 而非具体的内容( 这样修改的时候只用修改这个东西, 而非每一个使用到这个东西的地方 )
这个时候就出现了, 异常枚举类, BizExceptionEnum , 把所有异常的映射关系都存放到这里
比如ORDER_1( 10000 , "订单异常1号信息" ) 这样就用ORDER_1作为异常类的参数传递了 10000 和 "订单异常1号信息" 这两个信息, 而非直接把这两个信息作为异常类的参数进行传递
