你要知道HTTP报文中的Content-Type请求头确定了请求体中的内容是什么形式, 
因为针对HTTP报文它的请求体可以有非常多种形式, 而且还能有一些参数, 
Content-Type这个请求头就是确定这个的

但是浏览器发送报文只会给他发送的HTTP报文的只会采用Content-Type中的三种格式
```
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
```
application/x-www-form-urlencoded这个是重点
这个参数就指定了传递的内容没有二进制的内容, 所以都可以以键值对的形式去传递
也就是请求体里面都是
username = "你好"
这类数据


```
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryxxxx
```
multipart/form-data那需要传递二进制的数据就只能用这个传递了
首先你要知道, 二进制的数据有一堆& 空格 等奇怪符号会让解析数据很困难, 而且数据量也比较大, 用键值对不太合适
所以这个格式就是把传递的内容分块part, 每块用一些参数啥的去描述内容吧, 大概是这样, 所以在后端接收每次接收的都是一块内容, 
当然肯定有的内容是用键值对也可以传递的, 但是依旧会被分块, 但是虽然内容都被分块, 但是依旧可以用类, 变量啥的去接收, 底层会总动识别的
所以这个参数的主要作用就是可以传递二进制的内容


```
Content-Type: text/plain; charset=UTF-8
```
这个只能传递纯文本形式



这个是json请求体格式, 比较常用, 说说
```
Content-Type: application/json; charset=utf-8
```
现在你也懂了Content-Type请求头是干嘛的了, 所以这个就是指定报文请求体中的内容是json格式
