## @Tag
给@Controller类起名, 比如某个Controller类的职责是管理员工信息, 就起名 员工管理
@Tag( name = "员工管理" )
## @Operation
描述handle方法
@Operation( summary = "按照id查询单个员工" )

## @Parameters
描述请求方法的参数
请求方法的参数可以是, 路径变量/{id} 用@PathVariable注解的 , 
查询参数 URL中 ?后面的 用@RequestParam注解的 , 
请求头 用@RequestHeader注解的
其实还可以是用@RequestBody注解的纯json请求体, 但是请求体不用@Parameters去描述, 一会儿会说
```
@Parameters({  
        @Parameter(name = "id", description = "查询的员工id", in = ParameterIn.PATH, required = true),  
})  
@Operation(summary = "按照id查询单个员工")  
@GetMapping (value = "/employee/{id}")

public R<EmployeeResponseVO> get(@PathVariable("id") Long iddd) throws FileNotFoundException {  
 
 
    return R.ok(EmployeeResponseVO.from(es.getEmployee(iddd)));  
}
```

## @Schema
这个可以描述很多东西
比如, 参数是类, 或者返回值是类
就直接用这个注解去类里面描述就行
但是参数是类要在参数前面加上@Valid注解告知这个参数被描述了
@Valid @RequestBody Employee emp

```
@Schema(description = "响应体对象, 描述响应的状态信息")  
@Data  
public class R<T> {  
    @Schema(description = "本次请求的响应体状态码")  
    private Integer code;  
    @Schema(description = "本次请求的响应体信息")  
    private String msg;  
    @Schema(description = "本次请求的具体响应内容")  
    private T data;  
    
    public static<T> R<T> ok(T ret){  
  
        R<T> r = new R<>();  
        r.code = 200;  
        r.msg = "正常查询";  
        r.data = ret;  
        return r;  
    }  
}
```
看见了吗, 就想要描述哪个变量就加一个@Schema( descriptio = "" )就可以
