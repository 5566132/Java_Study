**按理说字符流的底层依旧是字节流, 事实上也是InputStreamReader这个类实现的这个步骤, 这个东西就是将读到的文本(数据本身都是字节), 包装成字符, 这一步是靠这个类内部的另一个类实现的,而另一个类有一个字节缓冲区去用来读字节**

**字符流的工作流程:**
**读入:**
**文本本身就是一堆字节, 字符流读入先把字节根据编码规则转变成字符存储,**
**写入:**
**写入时就只看字符而非底层的字节了, 读到某个字符将其根据编码规则转变成字节数据然后写入到指定路径**

**这个可以帮助理解乱码的出现是什么原因, 可以回想字节流的读入和写入是不会出问题的, 因为这个过程是没有编码转换的步骤的, 但是字符流有把字节变成字符再把字符变成字节的过程,如果把字节变成字符时编码规则与字节本身的规则不符合( 比如GBK下才是合理的字符, 但是用UTF-8去解码 )就会导致解码出来的字符是错的, 因此你再用对的编码规则去编码文本就肯定不对了,** 
**GBK下对的文本, 用UTF-8编码成字符, 再用GBK解码成字节到另一个文本, 就是乱码**
**那你肯定有疑问了, GBK下对的文本, 用UTF-8编码成字符, 再用UTF-8解码成字节不就对了吗**
**也不对, 因为规则不一样, 导致有的字节会被识别为无效序列, 然后java会将其替换成特殊字符,也就是底层的字节码给变了**


读入, 输出都是针对 字符 这个单元的操作, 
注意, 这个流只适合文本文件, 对于二进制文件(比如视频)就会出问题
FileReader fr = new FileReader(路径);
用这个读的东西就要用 char 或者 char`[]` 接收了,
fr.read()是返回本字符的组成字节的十进制表示形式, 
fr.read( char`[]` ) 这个则会返回读到的字符的个数, 
都是遇到文件末尾返回 -1

FileWrite fw = new FileWrite(路径);
把接收的字符写入指定路径
fw.write();
这个方法参数可以是一个字符, char形式或者int形式( 因为字符本身就是几个字节的二进制表示嘛, 二进制和十进制当然可以转换呀 )都可以
也可以是String, 参数可以指定起始索引和长度
当然也可以是 char`[]` 并且可以指定起始索引和长度

**字符流的特殊性:**
字符流在创建输入流的时候会同时创造一个缓冲区(长度为8192字节的数组)读取会先把这个缓冲区填满, 之后的读取都是读缓冲区的字节去转换成字符, 缓冲区读完就再把文本读入缓冲区, 这么做你要牢记一点 **磁盘IO开销大, 加入缓冲区相当于把磁盘IO变成内存IO,** 

创建输出流也是这个策略, 创建缓冲区, 当缓冲区满了, 或者调用flush() 或者close()会把缓冲区的内容写入到文本
