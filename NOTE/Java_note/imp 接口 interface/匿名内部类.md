在某些需要接收 类对象/接口实现对象 的场景可以选择用匿名内部类的形式去书写这个对象, 一部分原因是为了简化书写, 一部分原因可以让抽象方法更多样

匿名内部类的写法就是在需要用这个类对象的地方写
new Stu(){
	@Override
	public void swim(){
		System.out.println("本次实现可以写任意的具体实现, 不会影响其他");
	}
}
用匿名内部类的写法就只会对这个位置的类对象有影响 , 大概意思就是 真的创建了一个类对象/或接口实现对象, 但是你必须**重写**里面的所有 **抽象方法**

具体用途:
一般如果一个类实现了某个接口, 就需要在它的内部重写这个接口的所有抽象方法, 但是重写的时候肯定只能写一个固定的模式, 也就是不能做到因人而异, 假设, 我有多个场景都需要用到这个接口, 但是细节不同就很难只用一次重写做到满足所有需求, 这个时候用匿名内部类就很合适了, 每次重写都是不一样的实现, 
其实, 如果你的这个接口只会用到一两次也可以直接用匿名内部类去书写, 就可以不去实现接口了

还有, 这个东西跟Lamdba表达式有相似之处, 所以可以放在一起讨论
