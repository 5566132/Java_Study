这个东西只能用于**函数式接口** , 这个作用其实就是简化书写, 匿名内部类啥的是可以替代它的, 应用范围比他广, 但是没这个简介

函数式接口是指这个接口内部只有一个抽象方法, 也就是这个接口跟函数似的, 要是有两个接口就只能用匿名内部类了

具体就是如果某处需要接收一个  某某接口的实现类对象  而 这个接口恰好是函数式接口, 那我就完全可以用lambda表达式写

比如:
Arrays 的 sort方法 它的第二个参数就是一个 Comparator<>的接口
所以我在自定义比较函数的时候完全可以
Arrays.sort(arr, ( num1 , num2 ) -> { return num1 - num2 ; });升序排列

匿名内部类的写法则是
Arrays.sort(arr, new Comparator\<Integer>(){
	@Override
	public int compare(int num1, int num2){
		return num1 - num2;
	}
});依旧升序

对比来看, Lambda更加简洁
