## 提交流程, 分支切换到底是什么样子的?
##### 先说提交 , 也就是git commit 
首先, 你使用git时会看家master的分支提示, 这个就是告知你现在处于哪个分支![[Pasted image 20261011232641.png]]
这个时候你提交一个新的版本并非是创建了一个新分支, 而是创建了一个新提交, 可以这么理解, 基于当前分支(master)指向的提交, 延伸出一个子提交(也就是你的新提交), 将master分支移动到这个新提交
这其实也就回答了一个问题:为什么不要站在main分支上去提交?因为main分支基本都是上线版本, 你把上线版本给变成了你自己的提交肯定会出问题呀

##### 再说分支切换
所以, 你可以理解, 建议你用switch去创建新分支, 然后在你创建的分支去提交是为什么了吗, 
首先, 你创建一个分支(f1)之后是基于你现在所在的节点创建一个新的分支标记叫做f1,
然后把你现在处于的分支切换到f1就是这样![[Pasted image 20261011235928.png]]现在就相当于有两个分支指向了当前所在的这个版本, 这个时候你再提交版本就是基于f1去提交版本, 移动分支, 也就是你的main依旧保留在原来的位置, 也就是上线的版本没被改变
