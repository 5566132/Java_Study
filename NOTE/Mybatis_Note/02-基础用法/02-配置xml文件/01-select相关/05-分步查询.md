# 分步查询

## 为什么需要分步查询

> 外连接查询有点麻烦，能不能不用？
>
> 可以不用。

先前讲的一对一、一对多的查询，都是基于两个表用 `left join` 外连接查询实现的；但也可以用另一种形式去实现同样的结果——**分步查询**。

这里涉及到一个极其重要的要点：**自定义结果集 resultMap**（见 [[06-!!!自定义结果集resultMap]]）。

## 什么是分步查询

分步查询其实就是 `<association>` 或 `<collection>` 中的一个关键字：

- 不再依赖表连接一次查出全部数据；
- 而是利用多个 `select` 嵌套，上一个 `select` 查询出当前表的数据，再把查询到的字段值（`column`）作为参数，传给另一个 `Mapper.xml` 中的 `<select>` 去查询关联数据。

## 代码示例

```
<!-- 查询用户分步 -->
<select id="getCustomerById_orderSteps" resultMap="CustomerOrdersMP">
    select * from customer where id = #{id}
</select>

<resultMap id="CustomerOrdersMP" type="com.atguigu.mybatis.bean.cus_order.Customer">
    <id column="id" property="id"></id>
    <result column="customer_name" property="name"></result>
    <result column="phone" property="phone"></result>

    <collection property="orders"
                ofType="com.atguigu.mybatis.bean.cus_order.Order"
                select="com.atguigu.mybatis.mapper.cus_order.OrderMapper.getOrderByCustomerId"
                column="id">
    </collection>
</resultMap>
```

## 实现原理

1. 利用多个 `select` 嵌套，上一个 `select` 传递字段给 `resultMap` 这个自定义结果集；
2. 自定义结果集完成基本字段的映射；
3. 但在下面 类/集合 的映射中不使用字段匹配，而是利用其他 `Mapper.xml` 中的 `<select>` 去获得想要的 类/集合
