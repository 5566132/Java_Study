## 为什么 RAG 是后端工程师的主场

因为它的本质是 **检索 + 排序 + 缓存**——全都是后端的老本行。

| RAG 环节 | 对应的后端技能 |
|---|---|
| 文档切分、入库 | 批处理、离线任务 |
| 向量检索 | 索引设计、查询优化 |
| **混合检索 + RRF** | 多路召回、结果融合排序 |
| **语义缓存** | Redis 缓存策略 |
| 限流保护 Embedding 接口 | 令牌桶 |

## 学习清单

- [ ] **RAG 全流程**：切分 → Embedding → 向量检索 → 重排 → 拼上下文 → 引用溯源
- [ ] 文档切分策略：512-1024 token、重叠窗口、按语义切 vs 按长度切
- [ ] Embedding：什么是向量、相似度怎么算（余弦距离）
- [ ] 向量数据库选型：Chroma（学习）→ **pgvector（简历首选，复用后端 DB 经验）** → Qdrant / Milvus
- [ ] 🟡 混合检索：BM25 关键词 + 向量，用 RRF 融合
- [ ] 🟡 Rerank：为什么检索完还要重排
- [ ] 🔴 **幻觉控制**：引用溯源、无答案时拒答
- [ ] 🔴 **语义缓存**：用 Redis 缓存相似问题的答案
- [ ] 🟡 评测：建测试集 + LLM-as-judge
