### Spring-Boot-starter
这个东西就是核心场景启动器, 一般的场景starter内部(pom.xml文件中)都有核心场景启动器
大概来说, 这个东西就是存放多数场景启动器中所必备的部分, 然后写进场景启动器的starter去发挥作用

## Ai讲述

> 上面这句有个小修正, 见下面「哪些 starter 不带它」一节 —— 是**多半有**, 不是全都有。

---

## 它提供的 4 个功能

先看它的依赖清单（Spring Boot **4.1.1** 实测, 就 4 项）:

```
spring-boot-starter 4.1.1
├─ spring-boot-autoconfigure        372,740 B   ⭐⭐⭐ 自动配置引擎
├─ spring-boot-starter-logging        4,742 B   ⭐⭐  日志
├─ org.yaml:snakeyaml               340,068 B   ⭐   YAML 解析
└─ jakarta.annotation:jakarta.annotation-api  26,378 B   ⭐   Jakarta 注解
```

关键点: **这 4 个功能, 没有一个是和"Web"有关的。**
它提供的全是"一个 SpringBoot 应用能跑起来"的最低通用配置 —— 这就是它为什么叫"核心"。

---

### ⭐⭐⭐ 1. 自动配置引擎（最重要, 其他都是配角）

| | |
|---|---|
| **是谁** | `spring-boot-autoconfigure` |
| **多大** | 372,740 B —— **4 项里最重的一个, 比其他三个加起来还大好几倍** |
| **没了会怎样** | `@EnableAutoConfiguration` 完全失效 → **所有场景 starter 全部白导** |

它带来的核心资产是一份清单文件:

```
spring-boot-autoconfigure.jar
  └─ META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
        (12 个基础配置类: 配置绑定 / 占位符 / 消息源 / 定时任务 / SSL ...)
```

**为什么它是最重点**: 场景 starter 之所以"加一行就能用", 全靠这个引擎去读各模块的清单。
如果没有它, `spring-boot-starter-web` 就退化成一个"帮你下载 jar 的快捷方式" —— 依赖是进来了,
但没有任何东西会去自动注册组件。**starter 机制的地基就是它。**

→ 它具体怎么干活（反编译证据 + 完整链路）见 [[03-自动配置是怎么实现的]]

---

### ⭐⭐ 2. 日志

| | |
|---|---|
| **是谁** | `spring-boot-starter-logging` |
| **它又拉来谁** | `logback-classic` + `log4j-to-slf4j` + `jul-to-slf4j` |
| **没了会怎样** | 启动一片静默, 出错了看不到任何堆栈线索 |

`log4j-to-slf4j` 和 `jul-to-slf4j` 是**桥接包**: 它们把别的日志框架的调用
（Log4j2、JDK 自带的 `java.util.logging`）统一转发到 SLF4J, 最后落到 Logback。

**这就是为什么你能直接写**:

```java
private static final Logger log = LoggerFactory.getLogger(XxxService.class);
```
一行依赖都没单独导, 因为核心 starter 已经备好了。

**为什么标 ⭐⭐ 而不是 ⭐⭐⭐**: 它不影响功能正确性, 但**没有它你根本没法排错**,
所以实际开发中它的"体感重要性"仅次于自动配置。

---

### ⭐ 3. YAML 解析

| | |
|---|---|
| **是谁** | `org.yaml:snakeyaml` |
| **没了会怎样** | `application.yml` **读不了**（`application.properties` 仍然正常） |

负责把 YAML 文本解析成配置源。这也是**为什么 SpringBoot 推荐用 yml 而不是 properties**
—— 底层就是这个库在撑着。

> 注意一个反直觉的点: 它在 4.1.1 里是 **340,068 B**, 比日志那个 4,742 B 大 70 倍。
> 一个"只是读配置格式"的小库反而很占体积, 因为它是个完整的 YAML 解析器。

---

### ⭐ 4. Jakarta 注解

| | |
|---|---|
| **是谁** | `jakarta.annotation:jakarta.annotation-api` |
| **提供什么** | `@PostConstruct`、`@PreDestroy`、`@Resource` 等 |
| **没了会怎样** | 用到这些注解的地方**直接编译不过** |

Bean 生命周期相关的标准注解。注意它是 **Jakarta EE 的规范包, 不是 Spring 自己的**
—— SpringBoot 只是把它引进来方便你用。

> 这里有个版本坑: SpringBoot 2.x 时代是 `javax.annotation`, 3.x/4.x 换成了
> `jakarta.annotation`。**老教程里看到 `javax` 开头的 import, 就是 SB2 的代码, 直接照抄会编译失败。**

---

## 重点速记

```
⭐⭐⭐ spring-boot-autoconfigure   → 自动配置引擎（starter 机制的地基, 缺了整个体系失效）
⭐⭐   spring-boot-starter-logging → 日志（不影响功能, 但没有它没法排错）
⭐    snakeyaml                   → 让 application.yml 能读
⭐    jakarta.annotation-api      → @PostConstruct 等注解能用
```

一句话: **场景 starter 决定"你会什么", 核心 starter 决定"你能不能活"。**

## 哪些 starter 不带它（修正开头那句"一般都有"）

实测 4.1.1, **`spring-boot-starter-web` 是最出名的反例**:

```
spring-boot-starter-web 的直接依赖:
├─ spring-boot-starter-jackson     ← 它依赖核心
├─ spring-boot-starter-tomcat      ← 它依赖核心
├─ spring-boot-http-converter
└─ spring-boot-webmvc              ← 它依赖核心
                                    ★ 自己这 4 项里, 没有核心 starter
```

它是靠**传递依赖绕了一层**拿到核心的。所以开头那句应该改成:

> **大多数场景 starter 直接依赖核心 starter; `starter-web` 这类靠传递依赖间接拿到。**

故意不带的 3 类, 都是有理由的:

| starter | 为什么故意不带 |
|---|---|
| `spring-boot-starter-logging` | 它**自己就是核心的一块砖**, 带自己就循环了 |
| `spring-boot-starter-tomcat-runtime` | 纯运行时件, 和配置装配无关 |
| `spring-boot-starter-*-test` | 测试件。**故意不拉** —— 否则跑个单元测试会平白启动一整套生产级日志和自动配置 |

## 附: 3.x 和 4.x 的依赖清单不一样（别以为导错了）

```
spring-boot-starter 3.3.1 / 3.3.5         spring-boot-starter 4.1.1
    spring-boot            ← 有              (没了)
    spring-boot-autoconfigure                 spring-boot-autoconfigure
    spring-boot-starter-logging               spring-boot-starter-logging
    jakarta.annotation-api                    jakarta.annotation-api
    spring-core            ← 有              (没了)
    snakeyaml                                 snakeyaml
```

4.x 把 `spring-boot` 和 `spring-core` 两个**直接依赖**精简掉了, 它们改为间接拿到:

```
spring-boot-starter
  └─ spring-boot-autoconfigure
       └─ spring-boot          ← 核心本体从这里进来
            └─ spring-core
```

**classpath 上该有的仍然有, 不影响使用**, 只是声明更精确了。
这和"Boot 4 把自动配置按模块拆分"是同一个趋势: 少一点"顺便带上"。
